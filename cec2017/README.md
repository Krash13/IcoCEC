# ICO на бенчмарке CEC2017

Этот набор файлов позволяет тестировать алгоритм CountriesAlgorithm (ICO)
на официальном наборе тестовых функций CEC2017 (30 функций, безусловная
вещественная оптимизация, диапазон `[-100, 100]^D`).

## Состав

- `cec17_test_func.c` — оригинальная реализация функций CEC2017
  (Noor Awad / P. N. Suganthan,
  https://github.com/P-N-Suganthan/CEC2017-BoundContrained).
- `input_data/` — матрицы поворота, векторы сдвига и shuffle-данные,
  обязательные для корректной работы `cec17_test_func`.
- `cec2017.hpp` — C++-адаптер: оборачивает `cec17_test_func` в функции
  `cec2017::f1 ... cec2017::f30` с общей сигнатурой
  `double(const std::vector<double>&)`.
- `countries_algorithm_v2.hpp` — реализация алгоритма ICO.
- `benchmark.hpp` — запуск нескольких независимых испытаний и расчёт
  итоговой статистики.
- `main_cec2017.cpp` — точка входа: задаёт параметры ICO и запускает
  выбранные функции CEC2017 для указанной размерности.
- `meta_optimization_v3.cpp` — отдельная программа для настройки
  параметров ICO.

## Как задать размерность

Два способа:

1. Через переменную в коде — строка в `main_cec2017.cpp`:

   ```cpp
   int dim = 10; // допустимые значения: 2, 10, 20, 30, 50, 100
   ```

2. Через первый аргумент командной строки:

   ```bash
   ./ico_cec2017 30
   ```

   Значение из командной строки переопределяет значение `dim`, записанное
   в коде.

Допустимые размерности определяются данными оригинального бенчмарка
CEC2017: **2, 10, 20, 30, 50 и 100**. При другом значении программа
завершится с сообщением об ошибке.

Для `D = 2` отсутствуют необходимые данные для функций F11–F20, F29
и F30, поэтому программа автоматически пропускает их.

Сейчас в `main_cec2017.cpp` для короткого эксперимента выбраны функции
**F1, F3, F6 и F11**. Чтобы запустить все допустимые функции, удалите или
закомментируйте условие:

```cpp
if (entry.id != 1 && entry.id != 3 &&
    entry.id != 6 && entry.id != 11) continue;
```

## Сборка

Для сборки необходима библиотека Eigen3.

Из корневой папки репозитория выполните:

```bash
cmake -S cec2017 -B build
cmake --build build -j
cd build
./ico_cec2017 30
```

CMake автоматически скопирует `input_data/` рядом с исполняемым файлом.
При ручной сборке эту папку нужно скопировать самостоятельно:

```bash
cd cec2017
gcc -O2 -c cec17_test_func.c -o cec17_test_func.o
g++ -std=c++20 -O2 -I/path/to/eigen \
    main_cec2017.cpp cec17_test_func.o -o ico_cec2017 -lm
cp -r input_data build_dir/   # рядом с исполняемым файлом
cd build_dir
./ico_cec2017 30
```

Вместо `/path/to/eigen` укажите каталог, внутри которого находится
папка `Eigen`.

## Особенности CEC2017 и как они учтены в коде

- Известное оптимальное значение каждой функции:
  `f(x*) = funcid * 100`. Оно вычисляется функцией
  `cec2017::optimum_value(funcid)` и используется для расчёта ошибки
  `error = f - f(x*)`.
- Бюджет вычислений задан как `max_calls = 10000 * dim`.
- Функция F2 исторически исключена из официального сравнения CEC2017
  из-за расхождений между реализациями на разных платформах. Её реализация
  оставлена в коде. Если вы запускаете все функции и хотите исключить F2,
  раскомментируйте строку:

  ```cpp
  if (entry.id == 2) continue;
  ```

- Истинные координаты минимума `x*` скрыты в данных сдвига. Поэтому
  успешность определяется по значению функции, а не по расстоянию между
  найденной точкой и `x*`.
- Запуск считается успешным, если
  `abs(best_f - f(x*)) <= 1e-8`.
- В `main_cec2017.cpp` выполняется 20 независимых запусков каждой
  выбранной функции. Для полного официального протокола CEC2017 обычно
  используют 51 запуск.
- Число вычислений включает создание начальной популяции. ICO обрабатывает
  популяцию поколениями, поэтому последний шаг может немного превысить
  заданное значение `max_calls`.
