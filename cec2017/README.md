# ICO на бенчмарке CEC2017

Этот набор файлов позволяет тестировать алгоритм CountriesAlgorithm (ICO)
на официальном наборе тестовых функций CEC2017 (30 функций, безусловная
вещественная оптимизация, диапазон [-100, 100]^D).

## Состав

- `cec17_test_func.c` — оригинальная реализация функций CEC2017
  (Noor Awad / P.N. Suganthan, https://github.com/P-N-Suganthan/CEC2017-BoundContrained).
- `input_data/` — матрицы поворота, векторы сдвига, shuffle-данные,
  обязательны для корректной работы `cec17_test_func`.
- `cec2017.hpp` — C++ адаптер: оборачивает `cec17_test_func` в функции
  `cec2017::f1 ... cec2017::f30` с сигнатурой `double(const std::vector<double>&)`,
  совместимой с вашим `benchmark.hpp` / `CountedFunction`.
- `main_cec2017.cpp` — точка входа: запускает ICO на всех 30 функциях
  для заданной размерности.
- Ваши исходные файлы без изменений: `benchmark.hpp`, `countries_algorithm.hpp`,
  `test_functions.hpp`, `aggregators.hpp`.

## Как задать размерность

Два способа:

1. Через переменную в коде — строка в `main_cec2017.cpp`:
   ```cpp
   int dim = 10; // допустимые значения: 2, 10, 20, 30, 50, 100
   ```
2. Через аргумент командной строки при запуске:
   ```
   ./ico_cec2017 30
   ```
   (значение из CLI переопределяет переменную `dim` в коде).

Допустимые размерности определяются самими данными оригинального
бенчмарка CEC2017: **2, 10, 20, 30, 50, 100**. Другие значения приведут
к ошибке при старте программы.

Обратите внимание: для D=2 функции с ID 17–22, 29 и 30 (гибридные
и часть композиционных) не определены в оригинальном бенчмарке и
автоматически пропускаются в цикле.

## Сборка

```bash
mkdir build && cd build
cmake ..
cmake --build . -j
./ico_cec2017 30
```

CMake автоматически скопирует `input_data/` рядом с исполняемым файлом.
При ручной сборке (без CMake) не забудьте сами скопировать эту папку:

```bash
gcc -O2 -c cec17_test_func.c -o cec17_test_func.o
g++ -std=c++20 -O2 main_cec2017.cpp cec17_test_func.o -o ico_cec2017 -lm
cp -r input_data build_dir/   # рядом с исполняемым файлом!
./ico_cec2017 30
```

## Особенности CEC2017 и как это учтено в коде

- Известный оптимум каждой функции: `f(x*) = funcid * 100` — используется
  в `cec2017::optimum_value(funcid)` для расчёта ошибки (error = f - optimum).
- Официальный протокол требует `max_evals = 10000 * dim` — это уже заложено
  в `main_cec2017.cpp` как `max_calls`.
- Функция F2 исторически исключена из финального сравнения CEC2017 из-за
  несогласованности реализаций между платформами; она присутствует в коде
  (`cec2017::f2`), но по умолчанию пропускается в основном цикле (легко
  включить обратно, убрав `if (entry.id == 2) continue;`).
- Так как истинная точка минимума x* скрыта в файлах сдвига (shift data)
  и не сообщается напрямую, критерий "успеха" в отчёте `Result` строится
  по близости значения функции к известному оптимуму (`y_eps`), а не по
  L2-расстоянию до координат x* (координаты x* нам недоступны без
  дополнительного парсинга shift-файлов).
- Официальный протокол сравнения предполагает 51 независимый прогон на
  каждую функцию; в `main_cec2017.cpp` стоит `iterations = 20` — измените
  под свои нужды (полный протокол увеличит время расчётов).
